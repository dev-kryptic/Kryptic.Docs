# Dynamic secrets

Available on **Enterprise** (cloud) and on self-hosted keys that carry
`dynamic-secrets`. Free, Team, and Business never see the type. Staff-issued
Enterprise keys already include every licence feature if none are selected.

Kryptic stores encrypted provider config and lease metadata. A connector you run
(`kryptic connector run`) decrypts that config, talks to Postgres, MySQL,
Cassandra, Oracle, Redis, or AWS IAM, and uploads a minted envelope. The
platform never opens an admin password or a leased password.

<Note>
  After a downgrade, existing dynamic rows stay in the database and stay inert:
  no new leases, no provider envelopes handed out, bundles skip them. Unlinking
  or deleting the definition still works so you can clean up.
</Note>

## How a lease is minted

**Generate lease** in the dashboard needs the Kryptic daemon running and signed
in on the same machine. The browser probes `127.0.0.1:5278`. If nothing answers,
the drawer stops. The daemon then mints that lease. Other connectors in the org
do not see it.

App and CI leases are different: the daemon or `kryptic ci export` requests a
lease, and an online connector in that VPC polls due work, decrypts the provider
envelope, creates the user or STS session, and uploads a minted envelope. The
consumer decrypts that envelope on its machine.

If no connector is online for an app or CI lease, the request stays pending.
STS credentials can expire without a revoke call. Database users need the
connector to drop the role.

## Run the connector

Signed in on the desktop app, use **Operations → Start "Dynamic-Secrets" Connector** in the menu
bar or tray (or the same button in Open Kryptic). That opens a terminal
running `kryptic connector run --name local` and leaves mint and revoke
logs on screen.

A named connector, or a host without the app:

```bash
kryptic connector run --name vpc-east
```

Uses the signed-in daemon session. For a sidecar or CI job that can reach the
database:

```bash
export KRYPTIC_CLIENT_ID=kmi_...
export KRYPTIC_CLIENT_SECRET=...
# optional: KRYPTIC_SECRETS_API=https://secrets.example.com
kryptic connector run --name ci-job
```

The machine identity needs an org-key grant. Admin credentials are not in the
app bundle. A developer daemon only mints if it is also running as a connector.

## What the app receives

Daemon and CI inject `{KEY}_USERNAME` and `{KEY}_PASSWORD`. STS also sets
`{KEY}_SESSION_TOKEN` (and `{KEY}_ACCESS_KEY_ID` when AWS returns one). An
optional URL template on the definition fills `{KEY}` itself as a DSN.

## Templates

Shared on every provider: default TTL, max TTL (renew cannot pass it), username
template (`{{randomUsername}}`, `{{unixTimestamp}}`, `{{identity.name}}`,
`{{dynamicSecret.name}}`, `{{random N}}`, plus `truncate` / `replace` /
`uppercase` / `lowercase`), and editable create / revoke / renew statements.
