# Self-hosting

The management dashboard and the four product APIs run from
`Kryptic.Self.Hosting/compose/docker-compose.yml`. Images come from the Kryptic Nexus registry as
`nexus.webservices.theka.io/docker/kryptic/<name>:<version>`. Pin the compat
band (`1.3`). Every `1.3.Z` works with every other `1.3.Z`. Docs, the public
site, Public API, and Internal API are not in this stack.

Self-hosting requires a **Business or Enterprise licence key**. There is no free
self-hosted tier: the Free and Team plans are cloud-only. If you are still evaluating,
try Kryptic on a cloud plan first - self-hosting is bought, not trialled.

## Prerequisites

- Docker with Compose v2
- A host with 2 GB of RAM to spare
- (production) A reverse proxy terminating TLS in front of the exposed ports

## 1. Configure

```bash
cd Kryptic.Self.Hosting/compose
cp .env.example .env
docker login nexus.webservices.theka.io
```

Use the `kryptic_…` username from the registry-access email and the password
you set at `https://kryptic.dev/registry-access?token=...`. That login sits
next to any other registries you already use. It is only sent when you pull
from this host.

```bash
# .env (see .env.example for the full list)
POSTGRES_PASSWORD=$(openssl rand -hex 24)
TOKEN_KEY=$(openssl rand -hex 48)          # JWT signing key, 64+ chars
MASTER_KEY=$(openssl rand -base64 32)      # operational master key, exactly 32 bytes
MASTER_KEY_ID=key_master_v1
MANAGEMENT_CLIENT_URL=https://kryptic.example.com
MANAGEMENT_API_URL=https://api.kryptic.example.com
DAEMON_BFF_URL=https://daemon.kryptic.example.com
PIPELINES_BFF_URL=https://pipelines.kryptic.example.com
SECRETS_API_URL=https://secrets.kryptic.example.com
DOCKER_REGISTRY=nexus.webservices.theka.io/docker
KRYPTIC_VERSION=1.3
Deployment__SelfHosted=true
Licensing__LicenseKey=KRYPTIC-...
Licensing__PublicKeyPem="-----BEGIN PUBLIC KEY-----..."
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=
SMTP_PASSWORD=
SMTP_FROM=no-reply@example.com
SMTP_STARTTLS=true
SMTP_SSL=false
```

Leave `POSTGRES_HOST` empty to run the bundled database. Set it to your
existing Postgres host to skip creating a container (`./up.sh` does that).

Set `SMTP_HOST` (and usually `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`) so
invitations and approval mail actually leave the box. First-organization
signup does not send mail. Port `587` with `SMTP_STARTTLS=true` is the usual
submission setup. Port `465`
needs `SMTP_SSL=true` and `SMTP_STARTTLS=false`. Leave `SMTP_HOST` empty and
the same messages are printed on the API logs instead.

The licence key is a signed token. Plan, seat cap, and expiry are inside it.
The private half never leaves Kryptic, so editing the string cannot extend
the term or raise the seat cap. No key, a forged key, or a term past the
30-day grace window: the instance stays up and secrets stay readable. Writes
are refused. Reads never stop.

<Warning>
  Back up `MASTER_KEY`. It wraps the platform's operational data keys (SSO IdP
  credentials, directory-sync secrets). Losing it means those settings cannot be
  read back. Customer secret *values* are end-to-end encrypted under a
  client-held organization key and are not recoverable via `MASTER_KEY` - see
  [Encryption](/encryption). Rotation is supported: set a new `MASTER_KEY`, move
  the old one to `OldMasterKeys__<keyId>`, restart, and the platform rewraps
  operational data keys automatically.
</Warning>

## 2. Start

```bash
./up.sh up -d
```

| Service | Port | Purpose |
| --- | --- | --- |
| management client | 8080 | The dashboard your team signs into |
| Management API | 5210 | Serves the dashboard; runs migrations on startup |
| Daemon BFF | 5211 | What developer daemons talk to |
| Pipelines BFF | 5212 | CI/CD machine identities |
| Secrets API | 5213 | Public REST API v1 |

The other API hosts wait for the Management API. Because the Daemon BFF keeps
device logins and rate-limit state in Redis, API hosts can scale horizontally
behind your proxy.

## 3. Create your organization

Open the dashboard and register the first organization. There is no
confirmation email: you are signed in immediately. Then initialize encryption
under **Settings → Encryption** before anyone stores secrets. Invite your team.
Point developer daemons at your deployment:

```bash
kryptic config set-api https://daemon.kryptic.example.com
kryptic login
```

`KRYPTIC_API` overrides the saved URL without writing it, which is useful for a
one-off local BFF (`http://localhost:5211`). Changing the saved URL signs you
out, because tokens belong to one server.

CI runners use `KRYPTIC_PIPELINES_API` (compose: `http://localhost:5212`) with
[`kryptic ci export`](/cli#ci-export).

## Operations

- **Backups** - PostgreSQL is the only stateful service (`pgdata` volume). Standard
  `pg_dump` on your schedule. Also back up `MASTER_KEY` and the Emergency Kit
  shown at org-key setup, in two different places.
- **Upgrades** - `docker compose pull && docker compose up -d`. Migrations apply
  automatically.
- **Licence expiry** - on expiry the deployment keeps working for a 30-day grace window,
  then goes read-only: secrets stay readable, writes are refused. Reads never stop, in any
  state. The grace month is billed on renewal.
- **Multi-instance** - the Daemon BFF uses Redis for device logins and rate limits, so
  API hosts can scale horizontally behind your proxy.

## Helm

The chart is published under `kryptic-selfhost/helm` in Nexus. Use the same
`kryptic_…` registry-access user for `helm install --repo` and for the
image pull secret. Copy `helm/values.example.yaml` to a local file, fill
the keys, and pass it with `-f`. Helm `--version` is the chart release
(`1.3.4`). Pin images with `KRYPTIC_VERSION` (`1.3` follows the latest
`1.3.Z`).

```bash
helm install kryptic \
  --repo https://nexus.webservices.theka.io/repository/kryptic-selfhost/helm \
  --username <registry-access username> \
  --password <password> \
  --version 1.3.4 \
  --namespace kryptic --create-namespace \
  -f kryptic-values.yaml
```

Licence key and public PEM go in `Licensing__LicenseKey` and
`Licensing__PublicKeyPem` (chart values, same names as Compose). It routes:

| Host | Service |
| --- | --- |
| `kryptic.example.com` | management dashboard |
| `api.kryptic.example.com` | Management API |
| `daemon.kryptic.example.com` | Daemon BFF |
| `pipelines.kryptic.example.com` | Pipelines BFF |
| `secrets.kryptic.example.com` | Secrets API v1 |

External PostgreSQL and Redis are supported by pointing `POSTGRES_HOST` and
`REDIS_HOST` at those servers (leave them as `postgres` / `redis:6379` for
the bundled ones).

<Note>
  The Terraform module and the air-gapped installation bundle are not shipped
  yet. Offline licence validation already works: the key is self-contained and
  verified against the public PEM you ship with it, so an online install and
  an air-gapped one run the identical routine.
</Note>
