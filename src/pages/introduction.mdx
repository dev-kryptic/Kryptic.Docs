# Introduction to Kryptic

Kryptic is a developer secrets platform that injects environment variables at runtime - no `.env` files in your repo, no secrets in CI config.

A local daemon authenticates once via your browser, then your apps pull secrets over a local socket at startup. Add a `kryptic.json` to your repo root and one SDK line - that is the entire integration. Works on macOS, Linux, and Windows.

## Open-source clients

Anything that can see a secret in plaintext is open source and lives under
[github.com/dev-kryptic](https://github.com/dev-kryptic). The server platform is
proprietary: it stores ciphertext it has no path to open. See
[Encryption](/encryption).

| What | GitHub | Published as | License |
| --- | --- | --- | --- |
| Daemon and CLI | [Kryptic.Daemon](https://github.com/dev-kryptic/Kryptic.Daemon) | `kryptic` binary | GPL-3.0 |
| Encryption engine (.NET) | [Kryptic.Encryption.Net](https://github.com/dev-kryptic/Kryptic.Encryption.Net) | NuGet `Kryptic.Encryption` | Apache-2.0 |
| Encryption engine (TypeScript) | [Kryptic.Encryption.NPM](https://github.com/dev-kryptic/Kryptic.Encryption.NPM) | npm `@krypticdev/encryption` | Apache-2.0 |
| Encryption engine (Go) | [Kryptic.Encryption.Go](https://github.com/dev-kryptic/Kryptic.Encryption.Go) | Go module of the same name | Apache-2.0 |
| Kubernetes operator | [Kryptic.K8s.Operator](https://github.com/dev-kryptic/Kryptic.K8s.Operator) | GitHub Release + `ghcr.io/dev-kryptic/kryptic-operator` | Apache-2.0 |
| Language SDKs | [Kryptic.Net](https://github.com/dev-kryptic/Kryptic.Net), [Node](https://github.com/dev-kryptic/Kryptic.Node), [Python](https://github.com/dev-kryptic/Kryptic.Python), [Java](https://github.com/dev-kryptic/Kryptic.Java), [Go](https://github.com/dev-kryptic/Kryptic.Go), [Ruby](https://github.com/dev-kryptic/Kryptic.Ruby), [Cpp](https://github.com/dev-kryptic/Kryptic.Cpp), [Rust](https://github.com/dev-kryptic/Kryptic.Rust) | `Kryptic.Daemon.Client` / `@krypticdev/daemon-client` / `kryptic-daemon-client` | Apache-2.0 |

Each Kryptic SDK is intentionally thin: one entry point that talks to the local
daemon. It contains no authentication or secret-storage logic.
