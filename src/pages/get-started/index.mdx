# Quickstart

Get Kryptic running locally in four steps. Total time: about three minutes.

## 1. Install the daemon

Download the binary for your platform from the [download page](https://kryptic.dev/download),
or grab it straight from [GitHub releases](https://github.com/dev-kryptic/daemon/releases).
The install scripts register the daemon to start at login (LaunchAgent on macOS, systemd user
service on Linux, tray app on Windows).

<CodeGroup title="Install the daemon">
```bash title="macOS"
curl -LO https://github.com/dev-kryptic/daemon/releases/latest/download/kryptic_darwin_arm64
chmod +x kryptic_darwin_arm64
./install.sh kryptic_darwin_arm64
kryptic login
```

```bash title="Linux"
curl -LO https://github.com/dev-kryptic/daemon/releases/latest/download/kryptic_linux_amd64
chmod +x kryptic_linux_amd64
./install.sh kryptic_linux_amd64
kryptic login
```

```powershell title="Windows"
Invoke-WebRequest https://github.com/dev-kryptic/daemon/releases/latest/download/kryptic_windows_amd64.exe -OutFile kryptic_windows_amd64.exe
powershell -ExecutionPolicy Bypass -File install.ps1
kryptic login
```
</CodeGroup>

The rotating session token is stored in your OS credential store (Keychain, Credential
Manager, or libsecret). Access tokens live in daemon memory only.

## 2. Add kryptic.json

Commit a project config to your repo root. It contains no secrets - safe for version control.
Your project's exact file is on the project page in the [dashboard](https://app.kryptic.dev),
one click to copy.

```json
{
  "projectId": "proj_a1b2c3d4e5f6",
  "defaultEnvironment": "development"
}
```

## 3. Add the package for your language

One dev dependency, one line at startup. Every package is a thin Apache-2.0 client that
asks the daemon for your secrets over a local socket - see the per-language pages for
.NET, Node.js, Python, Java, Go, Ruby, and C++.

<CodeGroup title="Install package">
```bash title=".NET"
dotnet add package krypticdev
```

```bash title="Node.js"
npm install --save-dev krypticdev
```

```bash title="Python"
pip install krypticdev
```

```xml title="Java"
<dependency>
  <groupId>dev.kryptic</groupId>
  <artifactId>krypticdev</artifactId>
  <version>0.1.0</version>
</dependency>
```

```bash title="Go"
go get github.com/dev-kryptic/krypticdev
```

```ruby title="Ruby"
# Gemfile
gem "krypticdev", group: :development
```

```cmake title="C++"
include(FetchContent)
FetchContent_Declare(
  krypticdev
  GIT_REPOSITORY https://github.com/dev-kryptic/krypticdev-cpp.git
  GIT_TAG v0.1.0
)
FetchContent_MakeAvailable(krypticdev)
target_link_libraries(your_app PRIVATE krypticdev)
```
</CodeGroup>

<CodeGroup title="Startup code">
```csharp title=".NET"
using KrypticDev;

var builder = WebApplication.CreateBuilder(args);
builder.Configuration.AddKryptic();
```

```js title="Node.js"
// top of your entry point
require('krypticdev').inject();
```

```python title="Python"
import krypticdev
krypticdev.inject()
```

```java title="Java"
public static void main(String[] args) {
    Kryptic.inject();
}
```

```go title="Go"
func main() {
    krypticdev.Inject()
}
```

```ruby title="Ruby"
Kryptic.inject! if Rails.env.development?
```

```cpp title="C++"
int main() {
  kryptic::inject();
}
```
</CodeGroup>

## 4. Run your app

<CodeGroup title="Run command">
```bash title=".NET"
dotnet run
```

```bash title="Node.js"
npm run dev
```

```bash title="Python"
python manage.py runserver
```

```bash title="Java"
./mvnw spring-boot:run
```

```bash title="Go"
go run .
```

```bash title="Ruby"
bin/dev
```

```bash title="C++"
cmake --build build && ./build/your_app
```
</CodeGroup>

That's it. Secrets are in `process.env` (or `IConfiguration`, `os.environ`, `ENV`, …)
before your code reads them. Existing environment variables are never overwritten, and in
production the package is a no-op.

<Success>
  Your workflow did not change: F5, `npm run dev`, `dotnet run` - everything just works,
  and there is no `.env` file in your repo to leak.
</Success>

<Note>
  The daemon serves secrets only for projects and environments your account can access -
  access is checked on the server for every bundle, and every read is audit-logged.
</Note>
