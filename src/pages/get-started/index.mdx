# Quickstart

Get Kryptic running locally in four steps. Total time: about three minutes.

## 1. Install the daemon

Open the [download page](https://kryptic.dev/download). It detects your OS and architecture
and serves the current installer from kryptic.dev.

<div className="not-prose mb-6 mt-4 flex gap-3">
  <Button href="https://kryptic.dev/download" arrow="right">Download the daemon</Button>
</div>

- **macOS:** signed `.pkg` for Apple Silicon or Intel. Puts Kryptic in Applications and starts it at login.
- **Windows:** signed setup `.exe`. Installs the CLI, starts the tray app, and adds Kryptic to PATH.
- **Linux:** the one-liner below, or a `.deb` from the download page. Registers a systemd user service.

After the installer finishes, open a new terminal and sign in (or use the menu bar / tray):

```bash
kryptic login
```

Approve the code in your browser. The rotating session token is stored in your OS credential
store (Keychain, Credential Manager, or libsecret). Access tokens live in daemon memory only.

Optional, download from the terminal instead:

<CodeGroup title="Install from the terminal">
```bash title="macOS"
# Apple Silicon. Intel: https://kryptic.dev/dl/macos-intel.pkg
curl -fL -o Kryptic.pkg https://kryptic.dev/dl/macos-apple-silicon.pkg
open Kryptic.pkg
```

```bash title="Linux"
curl -fsSL https://kryptic.dev/install.sh | sh
```

```powershell title="Windows"
curl.exe -fL -o Kryptic-Setup.exe https://kryptic.dev/dl/windows-amd64.exe
Start-Process .\Kryptic-Setup.exe
```
</CodeGroup>

<Note>
  On Linux without `dpkg`, the one-liner installs to `~/.local/bin`. Add that directory
  to your `PATH` if `kryptic` is not found after install.
</Note>

## 2. Add kryptic.json

Commit a project config to your repo root. It contains no secrets - safe for version control.
Your project's exact file is on the project page in the [dashboard](https://app.kryptic.dev),
one click to copy.

```json
{
  "projectId": "proj_a1b2c3d4e5f6",
  "defaultEnvironment": "development"
}
```

## 3. Add the package for your language

One dev dependency, one line at startup. Every package is a thin Apache-2.0 client that
asks the daemon for your secrets over a local socket. Published names are
`Kryptic.Daemon.Client` (.NET), `@krypticdev/daemon-client` (npm), and `kryptic-daemon-client` on the other registries.

<CodeGroup title="Install package">
```bash title=".NET"
dotnet add package Kryptic.Daemon.Client
```

```bash title="Node.js"
npm install --save-dev @krypticdev/daemon-client
```

```bash title="Python"
pip install kryptic-daemon-client
```

```xml title="Java"
<dependency>
  <groupId>dev.kryptic</groupId>
  <artifactId>daemon-client</artifactId>
  <version>0.2.0</version>
</dependency>
```

```bash title="Go"
go get github.com/dev-kryptic/Kryptic.Go
```

```ruby title="Ruby"
# Gemfile
gem "kryptic-daemon-client", group: :development
```

```cmake title="C++"
include(FetchContent)
FetchContent_Declare(
  kryptic-daemon-client
  GIT_REPOSITORY https://github.com/dev-kryptic/Kryptic.Cpp.git
  GIT_TAG v0.1.0
)
FetchContent_MakeAvailable(kryptic-daemon-client)
target_link_libraries(your_app PRIVATE kryptic-daemon-client)
```

```toml title="Rust"
# Cargo.toml
[dependencies]
kryptic-daemon-client = "0.1"
```
</CodeGroup>

<CodeGroup title="Startup code">
```csharp title=".NET"
using Kryptic;

var builder = WebApplication.CreateBuilder(args);
builder.Configuration.AddKryptic();
```

```js title="Node.js"
// top of your entry point
require('@krypticdev/daemon-client').inject();
```

```python title="Python"
import kryptic
kryptic.inject()
```

```java title="Java"
import dev.kryptic.Kryptic;

public static void main(String[] args) {
    Kryptic.inject();
}
```

```go title="Go"
import "github.com/dev-kryptic/Kryptic.Go"

func main() {
    kryptic.Inject()
}
```

```ruby title="Ruby"
require "kryptic"
Kryptic.inject! if Rails.env.development?
```

```cpp title="C++"
#include <kryptic/kryptic.hpp>

int main() {
  kryptic::inject();
}
```

```rust title="Rust"
fn main() {
    kryptic::inject();
}
```
</CodeGroup>

## 4. Run your app

<CodeGroup title="Run command">
```bash title=".NET"
dotnet run
```

```bash title="Node.js"
npm run dev
```

```bash title="Python"
python manage.py runserver
```

```bash title="Java"
./mvnw spring-boot:run
```

```bash title="Go"
go run .
```

```bash title="Ruby"
bin/dev
```

```bash title="C++"
cmake --build build && ./build/your_app
```

```bash title="Rust"
cargo run
```
</CodeGroup>

That's it. Secrets are in `process.env` (or `IConfiguration`, `os.environ`, `ENV`, …)
before your code reads them. Existing environment variables are never overwritten, and in
production the package is a no-op.

<Success>
  Your workflow did not change: F5, `npm run dev`, `dotnet run` - everything just works,
  and there is no `.env` file in your repo to leak.
</Success>

<Note>
  The daemon serves secrets only for projects and environments your account can access -
  access is checked on the server for every bundle, and every read is audit-logged.
</Note>
