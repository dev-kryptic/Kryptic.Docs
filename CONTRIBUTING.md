# Contributing to the Kryptic docs

Corrections and improvements to the written documentation are welcome — typos,
wrong flags, stale output, missing steps, unclear explanations, whole new
guides. Every docs page has an **Edit on Github** link that drops you on the
right `.mdx` file.

## What can be changed by pull request

| Path | Open to PRs |
| --- | --- |
| `src/pages/**/*.mdx` | Yes — the documentation pages |
| `public/llms/**`, `public/llms.txt` | No — generated by `npm run gen:llm`, edit the `.mdx` source instead |
| everything else | No — site source and assets are proprietary (see [LICENSE](LICENSE)) |

Site source changes (components, styling, navigation chrome, build scripts) are
not accepted from outside contributors — the site source is proprietary, and
parts of it are shared with Kryptic's closed clients. If you have found a bug in
the site itself, please open an issue instead of a PR.

One exception worth knowing: adding a new page also needs a one-line route entry
in `src/components/NavigationDocs.jsx`, or the page will not appear in the
sidebar. Include that line in your PR — it is the only site-source edit we ask
for.

## Running the docs locally

```bash
npm install
npm run dev          # http://localhost:3000
```

Before pushing:

```bash
npm run lint:mdx     # heading structure
npm run build        # catches broken MDX, imports, and routes
```

Both CI checks that run on your PR are `pr-build` (lint and build) and
`codespell` (spelling). Getting them green locally saves a round trip.

## House style

- One sentence per line in `.mdx` where practical — it keeps diffs readable.
- Use the real command output, not an approximation of it.
- Product names: **Kryptic**. In public copy the language clients are *SDKs*. Use *package* only for the NuGet, npm, PyPI, Maven, or RubyGems artifact.
- Prefer showing the smallest command that works over explaining every flag.
- Screenshots: don't add new ones. Ours are generated from an internal build.

## Reporting something you can't fix yourself

Open an issue at
[github.com/dev-kryptic/Kryptic.Docs/issues](https://github.com/dev-kryptic/Kryptic.Docs/issues).
If a doc is wrong in a way that could cause data loss or a security mistake, say
so in the title and we will prioritise it.

Security vulnerabilities in Kryptic itself should not go in a public issue —
email hello@kryptic.dev instead.
